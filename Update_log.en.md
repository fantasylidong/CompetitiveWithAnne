### July 16, 2026 New-Player Download Optimization
- Reworked FastDL scheduling in `l4d2_blackscreen_fix.smx`. New players now download hit-feedback icons and non-built-in feedback sounds first, while dance assets are filled in during real map transitions.
- `restrict_strings.cfg` is now the first-connect priority list, containing 44 feedback material files and 17 deduplicated feedback sound files. Dance models are no longer downloaded on the initial connection.
- Added `deferred_strings.cfg` for the 60 dance songs, split into eight groups by default. Each actual `changelevel` offers one shuffled group; no group repeats until all eight have been offered, after which the order is shuffled again. `sm_fixscreen_deferred_group_count` controls the number of groups, and files already present in the client cache are skipped automatically.
- The three interdependent dance model files are downloaded together on the player's first map transition to prevent partial-model errors. The same transition also offers one random song group, and later transitions continue in shuffled, non-repeating order.
- All 124 feedback, model, and dance resources are now stored as path-preserving `.bz2` files in the NewAnneWeb file manager. FastDL now uses `http://anne.trygek.com/fastdl/left4dead2` with Cloudflare edge caching.

### August 13, 2026 infected_control Audit Fixes
- Upgraded `infected_control.smx` to 2026-08-13.2 with fixes from a full code audit. The wave-timing contract (kill phase, independent 16-second base countdown, unbounded Anti-Bait hold) is unchanged.
- Fixed double counting of alive specials: full-scan recounts such as `RecalcSiCapFromAlive` now skip clients already in the kick queue, so teleport kicks no longer prematurely fill class/total caps.
- Fixed a deadlock where a failed progress export after a dynamic Nav topology rebuild (elevators, etc.) kept spawn searches pending forever; the pending flag is now cleared and legacy flow buckets take over, restoring the Director fallback.
- Fixed cross-map cache pollution: the survivor-flow fallback value and the per-bucket alive-SI count cache are now reset on round/map cleanup, so a lower `GetGameTime` on the next map can no longer revive stale data; also freed two ArrayList handles leaked on every bucket build.
- Hardened the Nav bucket disk cache: a cache whose metadata matches but contains no usable areas is deleted and rebuilt, and a failed export now removes the partial file instead of leaving it for the next load.
- Fixed two teleport-supervision issues: an unknown spawn time is no longer treated as a permanent spawn grace (specials adopted after a watchdog hard recovery are re-stamped and can be teleported again), and Smokers now accumulate invisibility ticks while their ability is on cooldown instead of restarting the count once ready.
- Improved the `GetNextSpawnTime` native: during the kill phase it returns the upper-bound "remaining check window + full base countdown", and while paused it falls back to the frozen wave clock instead of conflating kill-phase time with the base countdown.
- Anti-Bait state machine redesign: clearing a hold by spreading now requires sustained confirmation — the new `inf_antibait_spread_confirm` (default 3 seconds) demands the formation stay spread continuously before Pressure demotes. Briefly stepping away and immediately regrouping no longer tricks the intensive hold, and spreading no longer resets the stall clock. A team that regroups while still stalled inside the arm window re-enters Pressure directly as a continuation of the same hold.
- Decoupled the Anti-Bait progress snapshot: a survivor flow-read failure (elevator, bad Nav) no longer counts as a "vulnerable" member that wrongly blocks or releases holds; such members still participate in formation statistics and are only excluded from flow statistics. Flow baselines rebuild when readings recover, also without resetting the stall clock.
- Traitor materialization is no longer capped by `totalSI`: a traitor in the SpawnAllowed state whose release wave has arrived (their slot was already deducted from that wave's AI budget) may materialize even when leftover AI temporarily fills the limit; AI backfilling pauses on its own while over cap.
- `create_panic_event` now uses a rolling 60-second window refreshed by every new panic event and cleared immediately by `panic_event_finished`; this prevents custom maps that never send the finish event from silently bypassing Anti-Bait for the whole round, while continuous/infinite horde scripts keep refreshing the window unaffected.
- `sm_wavestatus` and the Nav debug command replies now use translation phrases (12 new phrases across zh-CN/zh-TW/en/ja/ko/vi) instead of hard-coded Chinese.
- The "healthy survivors + no Tank" mercy gates on the early countdown trigger are confirmed as intentional design and are now documented in the AGENTS.md behavioral contract (together with the spread-confirmation and traitor-exemption semantics).

### 2026-09-03 SI bunny-hop: no speed gain on the first hop

- Diagnosis: the shared air-correction code in `ai_path_movement.inc` never adds speed (it only floors the speed at or below the take-off speed and deducts for turning). The "first hop suddenly speeds up in mid-air" feel on all four SI came entirely from the take-off frame: the Path / Direct take-off replaced the velocity with `run speed + a full impulse` (Charger 250→350, +40%; Boomer 175→325, +86%, and `ClientPush` additionally forced any speed ≤250 up to 251) instead of gaining speed on landing like a human bunny-hop.
- `ai_path_movement.inc` gains hop-chain tracking: `AIPathMovement_NotifyGrounded` is called as early as possible on every grounded (or ladder) frame, and touching the ground after being airborne for at least 0.1 s counts as a landing regardless of whether the bot left the ground via a plugin hop, an engine jump or by walking off a drop along its path; falls from height count too, with no airborne time cap, so the speed carried out of a fall is kept and the landing hop still gets its impulse. `AIPathMovement_GetHopImpulse` returns the full impulse only when the bot re-jumps within 0.15 s of a landing; the first hop taken straight from the ground gets 0 and only changes direction. `AIPathMovement_MarkHopStart` consumes the landing grant on every take-off (called automatically by `BeginPathHop`); if the engine refuses the jump the bot is still standing on the next frame without ever leaving the ground, which does not count as a landing, so repeated ground attempts can no longer collect an impulse every frame. Ladders count as ground, so the first hop after climbing gets no impulse.
- `ai_charger3` to 1.0.1.12: Path and Direct ground take-offs use the landing impulse; the final pre-charge hop registers a take-off so the chain continues if the Charger drops back to approach; the chain is reset for a new Charger / on respawn. Debug logs now include ground speed and whether the hop was a landing hop.
- `ai_tank3` to 1.0.0.12: the normal hop (forward/back/side impulse) and the Path look-ahead hop both switch to the landing impulse; chain reset on round start and client connect.
- `ai_boomer_3` to 3.0.9: push force applied on landing only; the take-off velocity is built first and shared by the route check and the Teleport (the route check previously looked only at the push vector, which would have degenerated to a zero-length check on a push-less first hop); the 251 minimum hop speed now applies only on hops that actually add the push, so it can no longer sneak speed into the first hop.
- `ai_spitter_3` to 3.0.8: push force applied on landing only; `spitterDoBhop` writes back the already route-checked take-off velocity instead of recomputing one before the Teleport.
- The impulse cvar descriptions of all four plugins now read "added when re-jumping right after landing; the first hop taken straight from running gets none". The acceleration chain is simply shifted one hop later; caps, air correction and turn speed loss are unchanged.

### 2026-09-08 Charger melee-standoff stutter and endless stalemate fix (ai_charger3 1.0.1.14)

- **Symptom**: with the Charger on low health and the survivor holding a melee weapon, the Charger stuttered inside the bait band — dash, hard stop, dash, hard stop — and the standoff could last forever.
- **Direct cause of the stutter**: `maintainMeleeBaitDistance` was a bang-bang controller — full-speed retreat below `baitZoneMin`, full-speed advance above `baitZoneMax`, and a 35-unit deadzone in between that zeroed horizontal velocity with `TeleportEntity` every tick. A 1-unit error and a 30-unit error both used `runTopSpeed`, so the Charger crossed the whole band in 3-5 ticks and settled into "burst out at full speed, snap to zero, survivor steps in, burst again".
  - Distance control is now **hysteresis + proportional speed + minimum dwell**: once moving, it travels to the band center before releasing (a direction flip must cross half the band); speed scales with the distance error to that center, reaching full speed only at `BAIT_MOVE_SPEED_RAMP`, with a 35% floor; a direction is held for at least `BAIT_MOVE_HOLD_TIME` (0.25s).
  - The deadzone no longer zeroes velocity; it decays it by 0.7 per tick, so the Charger coasts to a stop instead of snapping to one.
  - After a retreat hop lands, a 0.45s lock prevents distance control from immediately turning back in, killing the per-tick fight between "hop out, advance on landing, too close again, hop out".
- **Inverted emergency threshold**: the emergency retreat line was hard-coded at `melee_range + 20` (90), which lands *inside* the bait band (85-120) — the innermost 5 units of the band were permanently in "emergency", where the retreat hop overrode the deadzone, so the Charger was told to hop again the moment it backed off to 85. The line now sits inside the band (`melee_range + min(20, baitZoneMinRange × 0.5)` = 77.5), making the full 35-unit band genuinely holdable.
- **The safety-net forced charge never fired**: the `ai_charger3_bait_max_duration` (7s) fallback in `isTargetVulnerable` hung off the Bait state's `getStateDuration`, and the state `startTime` resets on every `transitionTo` — one retreat hop clears the exit line, and a single Bait → Approach → Bait round trip zeroed the timer, which is why the stalemate could run forever. The stalemate clock is now bound to "target + continuous melee bait" and keeps accumulating as long as two melee-bait moments are less than 2s apart, so Approach ↔ Bait churn no longer resets it.
- **Decision space for a low-health Charger**: of the three paths in `shouldChargeInMeleeBait`, "health above the melee kill line" is always false after the health nerf, and `isTargetVulnerable` nests the same health check for melee targets, leaving only "the survivor looked away". `isTargetVulnerable` does carry a generic attack-interval check, but it uses one "next attack > now + 0.5s" threshold for every weapon, so the usable window is (weapon refire delay − 0.5s) — the shorter the swing cycle the narrower it gets, and a fast melee (refire ≤ 0.5s) yields a zero-width window that never fires at all. Added a **whiff-punish** path using a 0.2s threshold for melee targets, so every melee leaves a real window and a low-health Charger gets an earned opening.
- **Stalemate escalation ladder**: past `ai_charger3_bait_max_duration` it escalates feint → forced charge → target switch. The feint pushes in to draw a swing (handing control back at the emergency line so the normal retreat hop pulls it out), turning the aimless in-out into a deliberate, rhythmic fake that the whiff-punish path then converts. When feints run out it charges anyway — trading a pin for its life beats twitching in place. A charge on cooldown only means "not yet", not "impossible", so it never switches targets just because the ability is down.
- **New cvars**:
  - `ai_charger3_melee_bait_orbit` (default 1): inside the band, circle tangentially instead of standing still, turning "twitching in place" into "circling you for an opening". A blocked orbit direction flips and retries; when both directions are unsafe it holds position rather than handing control back to native pathing (which would walk the Charger straight into the survivor and make things worse). Set 0 to restore standing still.
  - `ai_charger3_melee_bait_stalemate_switch` (default 0): the last rung — switch to another survivor when the ability is ready but the charge still cannot land (height unreachable / path blocked). Off by default; watch how the rest feels first.
  - `ai_charger3_melee_bait_blacklist_dur` (default 10.0): how long an abandoned target stays out of target selection. Without it `L4D2_OnChooseVictim` picks the same melee survivor straight back (usually the nearest one) and the switching itself becomes the new jitter. The blacklist is only a preference — `getClosestSurvivorAndValid` ignores it as a last resort so the Charger is never left without a target.
- Recompiled: `ai_charger3.smx`.

### 2026-09-09 Tiered Charger bunnyhop nerf (config only, no plugin change)

- **Why only the hops**: the Charger runs at 220, exactly like a survivor, so whether it ever gets on top of anyone comes down entirely to bunnyhopping. The hop parameters *are* its pressure. Everything here changes *how* it hops, never *whether* it hops — the Charger still visibly comes at you, it is just easier to shoot and easier to dodge, not a Charger standing around looking stupid. All changes live in the six tiers of `dynamic_ai_difficulty.cfg`; plugin source and behavior are untouched, and **the Neri tier (level6) sits exactly on the plugin defaults, identical to before**.
- **Side strafing (best value in the set)**: `ai_charger3_bhop_strafe_mindeg` / `maxdeg` across the tiers 8–18 / 14–28 / 20–38 / 25–46 / 28–52 / 30–55 degrees. Amplitude is `tan(random(mindeg, maxdeg))`, so 30–55° gives 0.58–1.43 and 8–18° leaves only 0.14–0.32 — the approach path is close to a straight line. ### 2026-09-15 Spitter landing spit re-press (ai_spitter_3 3.0.11)

- **Symptom**: On the Easy–Expert tiers the AI Spitter almost never got a spit out; it looked like it did not know how to use its ability.
- **Root cause**: With `ai_spitter3_air_spit` 0, an airborne `IN_ATTACK` is discarded outright — not queued, not deferred — so the only frame it can spit on is the one where `FL_ONGROUND` is set. Meanwhile the plugin itself re-jumps on every landing frame within `ai_SpitterBhopStartDistance` (2500 in all three Anne configs), and `z_spit_range` is far below that, so the entire spit range sits inside the hop radius. One hop stays airborne for `sqrt(2 * 56 / sv_gravity) * 2`, and `TickrateFixes` pins `sv_gravity` to 750, so about 0.77 s — at 100 tick that is 77 airborne frames plus 1 grounded frame, a ground duty cycle of roughly 1/78. Over 98% of frames had the attack button stripped, and the remaining under-2% still had to coincide with the AI's firing moment. The Extreme/Neri tiers were fine only because air spit is on there and they take the `buttons |= IN_JUMP` jump-spit path, which never checks the ground.
- **Landing re-press**: the spit that gets stripped in the air is timestamped (`SPIT_OWE_TTL` 1 s, slightly longer than one hop's airtime, so only the current hop's owed spit counts). On the first landing frame, if the target is still visible and the ability can still fire, the plugin presses attack for it and skips the jump for that one frame. Only that frame — the next one hops as usual, still within the 0.15 s landing-impulse window, so the hop chain is unbroken and keeps its full impulse. The re-press uses the AI's own aim: the `if (buttons & (IN_ATTACK | IN_ATTACK2)) AIPathMovement_Reset(spitter);` at the top of the function already disabled path correction for that hop, so `AlignFacing` no longer overrides facing — the plugin presses the button, it does not aim.
- **Hopping resumes the moment the spit is out**: the grounded attack branch used to strip `IN_JUMP` whenever `IN_ATTACK` was held, so a Spitter whose AI keeps the button down stuck to the ground. It is now gated on `spitReadyToFire()` (the `m_nextActivationTimer` timestamp has passed): the jump is suppressed only while the spit can still come out; once the ability is in its wind-up or on cooldown the held button is ignored and hopping continues.
- No new cvar and no per-tier values: this is a bug fix, not a nerf. Extreme and Neri have `ai_spitter3_air_spit` 1 and take the old jump-spit path unchanged.
