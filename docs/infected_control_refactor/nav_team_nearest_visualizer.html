一次普通刷特尝试的完整流程（team-nearest 分支）

0. 参与集合遍历生还者：存活、未被控、未倒地、未达目标容量（队首上限×2）→ (client, navId) 列表。任何成员移动/容量变化都会改变指纹 → 重置游标并重建快照。
1. 扩展快照worker 线程一次多源反向 Dijkstra（AnneBuildTeamNavCandidateSnapshot）：每个 Nav 得到「min 路径距离 + owner」；剔除距任意生还者 <250u 直线的区域；全体候选按 Flow 降序建 flowOrder。
2. 距离分层10 层固定边界 250/350/500/700/900/1150/1400/1700/2000/2400/3000，与职业 min/finalMax 相交后半开取层；空层直接跳过（AdvanceToUsableBand）。
3. owner 检查层内按 Flow 从前往后取候选：owner 已失效 → ownerInvalid++ 跳过；owner 已达容量 → ownerCapacity++ 跳过（不再重置游标）。然后把评估帧绑定到 owner（眼位/脚位/扇区中心/进度桶）。
4. 硬过滤Nav flags → 后方硬拒绝（cand−owner < −8，HJC −4；owner≥90% 时豁免）→ 冷却 → 同桶上限(默认关) → 随机点：分散/距离/排除圈 → 卡壳 → 可见性 → 路径可达。
5. 评分距离带契合、Flow 前后梯度（后方软扣分，HJC ×2.5）、高度、核密度、扇区历史 → 总分≤0 淘汰。
6. 选优刷出评分池收满 8 个或本层耗尽 → 最高分刷出，commit 记到 owner；全部层耗尽 → Director Range 兜底（2000u 直线上限）。
