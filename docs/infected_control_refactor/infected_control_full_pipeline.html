Wave scheduling

击杀阶段、独立倒计时与 Anti-Bait 延长串联执行

专家击杀阶段最多 8 秒；本波较快进入低压且异步队列已完成时会提前启动完整 16 秒倒计时。Anti-Bait 只在倒计时最后 4 秒允许接管，到点后可无限延长，解除条件稳定 2 秒才恢复刷特。

WaveDecider 状态机

每秒由 Timer_CheckSpawnWindow 更新；倒计时到点后调用 StartWave。

Anti-Bait 状态机

下中位数 Flow 判断全队是否推进，四人队需要至少三人移动；单人前探不会重置停滞计时。

Pressure 门槛

持续采样下中位 Flow 与队形，但只在倒计时最后 4 秒进入 Pressure；至少两名有效生还者、无人脆弱、停滞 12 秒且抱团稳定 2 秒才可延长。“脆弱”包含被控、倒地、挂边以及已阵亡——因此本局一旦有人阵亡，卡点无限延长整局不再生效（有意设计：队伍已减员时不再追加拦波压力）。

无限延长与恢复

16 秒到点仍满足条件便进入 IntensiveCheck，不设最长等待；下中位 Flow 推进 4%（或队伍质心位移 1000u）、队形拆组、出现孤立、间距达到 1500 或有人进入脆弱状态，连续 2 秒后立即放波。

保守边界

Anti-Bait 不绕过距离、视线、卡位与路径硬过滤，也不增加单帧 Nav 预算。高点、瓶颈与 Nav 拓扑暂不作为无限延长硬门槛，避免坏 Nav 造成永久误锁。

事件压力旁路

机关、尸潮和终局本身已经是压力，这时 Anti-Bait 整体让位：EventPressure_ShouldBypassAntiBait() 成立会把状态机 Reset 到 Off，并立刻结束正在进行的无限延长。这一层优先于所有队形与停滞判断。

暂停语义

暂停期间事件窗口冻结：EventPressure_GetTime() 返回暂停起点，解除暂停时把暂停时长补回所有截止时间。WaveDecider 与 Anti-Bait 的波次时钟同样按暂停时长整体后移。

延迟释放

机关若在暂停中触发而当时正处于无限延长，释放会被记为 eventReleasePending，等解除暂停后立刻放波，而不是在暂停中改变波次状态。

Tank 不是事件

Tank 走另一条通道：IsTankPressureActive()（默认 1200u 内有 Tank）让 Anti-Bait 进入 Paused；远处的 Tank 不解除保持。

残局低血无药

所有站立生还者的实血都低于 inf_antibait_lowhp（默认 40），并且存活队员（含倒地）都没有医疗包、电击器、止痛药或针时，同样进入 Paused。倒地血不是实血。阈值设为 0 可关闭这条。

分散度是多层叠加，不是一条规则

“别老在同一个地方刷”由几个互相独立的机制共同保证：一部分是硬拒绝（直接淘汰候选），一部分是软扣分（只影响排序）。扇区量化层（波内扇区配额、最近扇区扣分）已于 2026-08-30 整套移除，方向偏好改由连续的战术几何分表达，分散度评分只剩核密度一项。

可落下质量怎么算

从候选点向下 Trace 最多 480u 找可站落点，再取落点到最近生还者的距离：≥450u 记 0，落在人身上记 1，中间线性。屋顶下方 480u 内没有落点（例如高塔顶）直接记 0——这正是「太高反而没用」的表达。这次 Trace 每个候选只做一次，高度分和高点奖励共用同一份结果。

为什么上限只有 20

最终分会被钳到 100。历史默认是 6 分/50u、上限 100，导致高于目标 ~190u 的优秀候选、~590u 的较差候选全部并列 100 分，距离/Flow/分散/战术分被整体抹掉。3 分/50u、上限 20 让它退回「同等条件下的决胜项」，优秀与较差候选在任何高度都保持约 17 分差距。

并列决胜

候选择优用 ±0.01 容差判断并列；最终分并列时改比 weightedQuality（未加高点奖励的四因子加权分），而不是取扫描顺序里的第一个。

落点预测：请求点通过不等于真的能刷

ZombieManager 会把请求原点向下吸附（常见约 10u，边缘几何上更多）。因此安全检查都对预测落点再跑一遍，而不是只信请求点。

可见性

IsPredictedSpawnLandingVisible 先固定检查 −10u；再向下 trace 求真实落地点；trace 拿不到稳定命中时补采样 −2 / −4 / −6u。任一样本可见即拒绝。

伤害区域

IsPredictedSpawnLandingInHurtTrigger 用玩家 hull 与所有 trigger_hurt / trigger_hurt_ghost 做 AABB 相交，并额外探到 −40u；实体列表每秒刷新一次并跳过 m_bDisabled。

卡位

WillStuck 用 16×16×71 的 hull 原地 trace；过滤器放行 blockType 1/2 的 env_physics_blocker（只挡生还者的隐形墙）。

API 点的复核范围

导演给的点会复核：距全队最近眼位 ≤ 2000u、≥ max(250, SpawnMin)+16（传送模式再取 TeleportMin）、硬分散半径、卡位、可见性、预测落点可见性、预测落点伤害区域。不复核：有向路径可达性、职业距离带、Flow 后点、Nav 冷却、Flow 桶占用与扇区配额——兜底的意义就是绕开这些质量约束。

创建即提交

当前刷特路径没有 pending 校验窗口：L4D2_SpawnSpecial 返回有效 index 即计入 siAlive/totalSI 并触发 InfectedControl_OnSpawnCommitted。2000u 上限只在请求点上判定，生成后不再按实际落点复核。

失败恢复

两段 API 都无点时轮换目标；目标轮完后按默认 0.10 秒退避，再从职业主区间开始。

运行时看门狗：刷特停摆会自愈

RuntimeWatchdog 挂在 OnGameFrame 上、每 1 秒跑一次。它不参与找位，只负责发现“本该在刷特却没在刷”的状态并纠正。排障时先看日志里的 [IC][RECOVERY] 与 [IC][RUNTIME]。

检测项判据动作
首波丢失生还者已出安全区但没有首波 timer重新 RequestStartSpawn
首波超时首波 timer 挂了 5 秒还没触发杀掉旧 timer 并重新排程
波状态 timer 失效句柄无效，或心跳超过 3.5 秒没更新重建 1 秒波 timer，不重置波次计时
传送 monitor 失效同上，且 inf_TeleportSi = 1重建传送 monitor
队列越界pending 预算为负、超过上限，或队列长度大于预算钳回区间并裁剪队列
特感计数漂移实际在场特感数与 totalSI 连续 2 tick 不一致RecalcSiCapFromAlive 全量重算

启动闸门

RequestStartSpawn 需要同时满足：回合活跃、地图未结束、未被 sm_stopspawn 抑制、回合已稳定 2 秒、且至少有一名可移动（未倒地）的生还者。被拦下时每秒最多打一条 Start request blocked。

幂等清理

所有 TIMER_FLAG_NO_MAPCHANGE 的 timer 都通过 StopTrackedTimer 先摘引用再 KillTimer，并在回调里比对自身句柄，因此地图切换时的重复清理是安全的。

临时态实体

已进入踢出队列的特感在任何全图清点里都被跳过（SpawnAttempts_IsTransientSpawnClient），否则传送回收的瞬间会被计两次、提前打满上限。

职业上限镜像

投票和管理员改职业上限时不直接写引擎 cvar，而是走一层镜像，避免和地图配置互相覆盖。这也是“我改了 z_hunter_limit 怎么没生效”的答案。

镜像 CVar

inf_smoker_limit / inf_boomer_limit / inf_hunter_limit / inf_spitter_limit / inf_jockey_limit / inf_charger_limit，默认全部 -1 = 跟随对应的 z_*_limit。

命令监听

插件监听 sm_cvar z_*_limit <n>，把值同步写进镜像。一旦某个职业的镜像被写成 ≥ 0，它就永久接管该职业上限，之后直接改引擎 cvar 不再生效，需要把镜像改回 -1。

z_max_player_zombies

插件按 l4d_infected_limit（内鬼 Tank 开启时 +1）设定它的上界并强制写值；每秒检查一次，被外部插件改大会被拉回。

热路径预算

高特上限时主要靠固定单帧预算稳定峰值，而不是靠降低刷特频率。

边界当前策略作用
